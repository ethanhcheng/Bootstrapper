## Edge Cases / Risks / Assumptions
- Edge cases handled:
  - The `Projects/Bootstrapper/scripts/bootstrap_agent_governance.sh`
    at the repo root is a thin wrapper that `exec`s the embedded
    bootstrap at `skills/agent-governance-scaffold/scripts/`. The
    wrapper itself is not in the templates, so it is never
    overwritten by `--auto-update`. The embedded copy IS the one
    whose `SCAFFOLD_VERSION` controls update detection.
  - `~/.claude/skills/agent-governance-scaffold/` had been over-mirrored
    earlier in the session (full skill tree). The deploy script only
    writes `SKILL.md` there, so the leftovers had to be cleaned by
    hand to match the documented Claude skill shape.
  - Bootstrapper had no `plans/2026-05.md` before this work. The
    `--auto-update` invocation in phase 3 invoked
    `ensure_current_month_plan`, which created it with the canonical
    monthly headings and the placeholder "Governance Bootstrap"
    block. Existing 2026-03 and 2026-04 monthly files were untouched.
  - The strict verifier failed with "drift" the first time it ran
    inside Bootstrapper because the two ported plan docs were on
    disk but not yet linked from INDEX. This is the EXPECTED design
    behavior — the verifier catches a real workflow violation. The
    fix was to update INDEX, not to weaken the verifier.
- Risks:
  - Existing scaffolded targets may have local customizations to
    managed files (AGENTS.md, CLAUDE.md, rule files). `--auto-update`
    overwrites those. The scaffold's design assumption is that rules
    are universal and project-specific overrides live in
    `BOOTSTRAPPER_SPEC.md`. If a target has customized rule content
    in-place, this update will clobber it. Mitigation: inspect each
    target's git status before running --auto-update (covered in
    phase 5 of the run-record below).
  - The deploy script clobbers `~/.codex/skills/agent-governance-scaffold/`
    via `rsync --delete`. Any plan entries we created inside the
    codex copy's `plans/` (the recursive-self-scaffold artifacts)
    are lost if not ported first. Mitigation: phase 4 step 7 copies
    them to Bootstrapper before phase 2 runs the destructive deploy.
    (Done; verified by file presence in Bootstrapper/plans/.)
  - InvoiceTracker-IS has pre-existing INDEX drift (18 unlinked docs +
    1 stale link). The strict verifier will fail inside that repo
    after --auto-update. This is reported, not auto-fixed.
- Assumptions:
  - `Projects/Bootstrapper` is the authoring source-of-truth going
    forward; `~/.codex/skills/` and `~/.claude/skills/` are deploy
    targets only. The user confirmed this when asked.
  - The wrapper-vs-embedded structure of the bootstrap script will
    not change; the embedded script's `SCAFFOLD_VERSION` is the
    correct lever for triggering propagation.
  - `update-local-codex-skill.sh` is the canonical deploy
    mechanism. Using it directly (vs `cp -r` or `rsync` by hand)
    keeps the deploy contract intact across all future iterations.
