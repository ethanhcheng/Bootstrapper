## Edge Cases / Risks / Assumptions
- Edge cases handled in the strict verifier:
  - Empty plans/ (no dated docs, empty INDEX): both sets empty, no
    drift, passes.
  - Non-dated files in plans/ (README, IDEAS, monthly files, template):
    excluded by the regex.
  - Dated docs with uppercase/underscore slugs: excluded by regex —
    this is intentional and consistent with the validation in
    `scripts/create-implementation-doc.sh`, which enforces lowercase
    kebab-case slugs.
  - Multiple INDEX links pointing at the same file: deduplicated via
    `set()`.
- Risks:
  - Existing scaffolded repos with non-conforming slugs (uppercase,
    underscores) would silently be ignored by the drift check. Low
    risk; the create script has always required lowercase
    kebab-case, so any existing non-conforming files were created
    by hand.
  - Agents may still ignore the "read INDEX first" instruction in
    practice, since there is no automated gate. Acceptable per user
    decision; mitigation is the rule wording in CLAUDE.md /
    AGENTS.md / .codex/PROJECT_RULES.md and in the shared
    dev-workflow rule, which now explicitly names the workflow.
  - The cursor/claude pair is enforced byte-identical by
    `sync-agent-rules.sh`; if a future edit lands in only one of the
    two files, the sync script will fail in --check mode. Mitigation
    is the existing alignment check, unchanged.
- Assumptions:
  - Markdown links in INDEX.md follow the canonical
    `[text](filename.md)` shape produced by
    `scripts/create-implementation-doc.sh`. Hand-edited links with
    different wrappers (HTML, relative path prefixes) would not
    match the regex; the verifier would treat the file as
    "missing from INDEX." Acceptable — the helper script is the
    expected creation path.
  - The instruction-only approach (no `@plans/INDEX.md` preload) is
    sufficient to remind agents to consult INDEX. If real-world
    usage shows agents ignore it, the fallback is re-introducing a
    preload — a one-line CLAUDE.md change.
